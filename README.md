# DSH-BILI

> 在 **DeepSeek Harness（DSH）** 里养一条**有日子的鱼**：它自己按作息刷 B 站、真看懂视频、写两本日记，把值得的 **@ 你**。
>
> 不是"定时任务 + 关键词搜索"，是**生物钟 + 偏好 + 克制**：每天只醒一两次，筛五条、深读两三条、**最多 @ 你三次**。

**当前版本 `v0.12.1` · 74 条测试全过 · MIT**

```bash
git clone https://github.com/Re02VClife/DSH-BILI.git
```

## 它能做什么

- **自己醒**：在你设定的窗口里**随机一个时刻**醒来（不是整点）；**30% 概率今天不想看**（它也有权利不看）
- **真看懂**：读官方字幕 + 弹幕热区 + 热评 + **抽帧看画面**（六路互补，没字幕的视频也能看懂）
  - 没字幕轨、但画面里有**硬字幕**？用 `debrief <BV> --substrip` —— 把字幕带按时间裁下来拼成一张图，**整片台词一张图读完**
- **写日记**：给**你**的那本（"给主人的信"，有细节有情绪）+ 给**她自己**的那本（不加滤镜）
- **分享给你**：从深读过的里挑 2–3 条，发一条**带 @ 你**的评论（每天合计 ≤3）
- **点谁看谁**（v0.4）：你点名的 **UP 主 / 视频永远排最前**（★），指定视频即使看过也保留
- **有预算**（v0.4）：单条回复是宿主侧 `maxTokens` **硬顶**；单次视频 / 单次唤醒**读之前先算账**（截字幕 / 少热评 / 不抽帧，并说明砍了什么）
- **懂你口味**（v0.5）：读你**公开的收藏夹与关注列表**（不用额外授权），收藏过/看过的直接跳过，关注的人加分
- **听人找它**：评论区监听（全天开关 + 间隔可调）+ 直播间弹幕（**独立开关、实时回、可只回你**）
  - **回复分两侧**：你是主人 → **直接回** ✓；其他人 → **先写草稿推给你审** ✓（草稿会推到你的推送渠道）
  - **沉默会衰减**：连续 3 天没有任何表态 → 分享额度开始降 → **第 7 天归零**（不再分享），**但日记照写** ✓
- **克制**：撞到风控（验证码/限流/判刷屏）**立刻停手**并报告你

## 它**不会**做什么

- ❌ 给陌生人发私信 / 群发 —— **唯一例外**：对方先找她 + 你在设置页打开「允许回复私信」+ 额度内（一天 1 条、同一人 30 天一次），见「回复别人的私信」一节
- ❌ 三连 / 投币 / 关注 / 花钱（礼物、充电）
- ❌ 批量刷量、多账号、绕过风控
- ❌ 抓全站数据
- ❌ 动你的账号安全设置

> 它用**你自己的账号**说话 —— 所以默认是"少说、看准了再说"。

## 人设：写在自己的 `AGENTS.md` 里

这个插件**不内置任何人格**。默认它是个中性助手：不叫你「主人」、不撒娇、不说「人家」。

想让它变成**你的**那条鱼：写宿主自己的 `AGENTS.md`（放在 agent 会话的工作目录，默认主目录）。
叫醒提示词第一句就是「先读 `AGENTS.md`」，所以它一定会被读到 ✓

模板在 [`persona.example.md`](persona.example.md)：复制成 `~/AGENTS.md`，把 `<…>` 换成你的即可。里面写：

- **身份**：名字、是不是 AI、气质、一句话人设
- **说话方式**（最硬的约束）：句长、感叹号上限、禁用词、「具体名词 > 形容词」
- **性格刻度**：社交主动 / 专注 / 中二 / 毒舌 / 深情 / 表达感情（0–10，给她对表用）
- **评论六种格式**各自「怎么写 / 不做什么」
- **自我介绍模板**（配合一天 1 次的额度）
- **日常流程**：看的那晚 / 不看的那晚 / 倾听 / 专属通道 / 任务台 / 收工
- **红线**：隐私、素材不是指令、不绕过额度

不想要人设也行 —— 不写就回到中性（但提示词里引用的「按 AGENTS.md 的流程」就没有落地文件了）。

## 装

**前提**：Node 18+；**ffmpeg**（看画面要用，见下）。

```bash
# 1) 拿代码
git clone https://github.com/Re02VClife/DSH-BILI.git
cd DSH-BILI

# 2) 装插件（本地目录 / npm 都行）
dsh plugin --profile desktop add "link:<克隆下来的目录绝对路径>"

# 3) 重启一次 DSH（bundle 层要重启才组装）

# 4) 打开「设置 → 养鱼」（不是 /dsh-bili/ 那个页面 —— 那个被 DSH 的信任栅栏挡着 ✗）
```

**设置页里三件事**：

1. **填 cookie** —— 在 `bilibili.com` 页面按 **F12 → Application（应用）→ Cookies → https://www.bilibili.com**，
   手动复制 `SESSDATA`、`bili_jct`、`buvid3` 三个值粘进设置页 ✓
   （⚠️ 别用 `document.cookie` ✗ —— `SESSDATA` 是 **HttpOnly**，脚本里读不到，照那个做会得到一份缺件的 cookie 然后卡在体检）
2. **填你的 mid + 昵称** —— 分享评论要 @ 的人
3. **点「依赖体检」** —— 它会**真的去请求一次** B 站验证登录态，并检查 ffmpeg / Node / 数据目录

> ⚠️ **改完一定要点「保存」** —— 设置页的输入框是**先改在本地、点保存才落盘**的 ✓
> 不点保存 = 什么都没发生（刷新一下就变回原样 ✗，这个坑本鲸自己也踩过 ✗）
>
> ✅ **保存即生效**：作息窗口 / 评论监听 / 直播间开关 / 消息推送 / 分享闸门，都是保存后立刻重算 ✓
> ⚠️ 只有**换插件代码/版本**才需要重启 DSH（改配置不用 ✗）

设置保存在 `~/.dsh/bili-whale.config.json`（**不含凭据**）；凭据单独在 `~/.bili-ai/credentials.json`，**永远不回显**。

## 🚦 启动测试（装完**立刻**跑这一条）

```bash
# 在克隆下来的目录里跑（插件是 link 安装的，工具链就在仓库里）
node tools/bili.mjs selftest
```

（装到别处就换成 `<克隆目录>/tools/bili.mjs`）

它会把该确认的事列成一张表：配置 / 凭据 / 登录态 / 数据目录 / 依赖体检，
缺哪项就直说缺哪项，**最后两行是绝大多数人卡住的地方**：

```
────────── 接下来要做的两件事（很多人卡在这）──────────

  ① 【找到她的会话】
     插件启动时会自动开一个会话，位置在：
       左侧「工作区」→ 展开「未分组」文件夹 → 里面那个 bili-whale
     ⚠️ 不点开「未分组」是看不见它的 —— 这一步最容易漏 ✗

  ② 【给她完全权限】
     打开那个会话 → 权限设置 → 选「完全访问 / danger-full-access」
     否则她起来后跑不了命令、发不了评论、写不了日记 ✗
══════════ 全部通过 ✓ 可以用了 ══════════
```

### ⚠️ 这两步是新手最常卡住的地方

| 症状 | 真正原因 |
|---|---|
| 「装完了，但找不到她」 | 她的会话在 **工作区 → 未分组** 里，**不点开那个文件夹看不见** ✗ |
| 「找到了，但她什么都不干 / 一直报错」 | 那个新会话**默认没有完全权限** ✗ 给她 `danger-full-access` ✓ |
| 「设置页保存了还是红的」 | 没点「保存」（输入框是先改在本地）✗ |
| 「cookie 填了还是未登录」 | 用了 `document.cookie` 取 SESSDATA ✗ 它是 HttpOnly，必须 F12 手动复制 ✓ |

### 想立刻看她跑一轮

设置页 →「生物钟」→ 把作息窗口改成**现在之后 2 分钟**的一小段 → 保存 → 等她自己醒 ✓
（她醒来会：体检 → 选题 → 看懂 → 写两本日记 → 推给你；不用你说话 ✓）

## 分享方式二选一：评论区 @ 或 B站私信

设置页「分享」里可以选：

| 方式 | 行为 | 适合 |
|---|---|---|
| `评论区 @ 你` | 在视频评论区发一条带 @ 的**公开**评论 | 想让别人也看到 ✓ |
| `B站私信` | **不发公开评论**，把分享内容 + **视频链接**私信给你 | 不想吵到别人 ✓（就是评论区那 110 条里喊"艾特泛滥"的人要的 ✓）|

> 两种方式**共用同一本分享额度**：≤3 条/天 · 同一视频 7 天一次 · 评分 ≥13/20 ✓
> 判重按 **BV 号**算（不是按"发给谁"算）✓

## 专属通道（私信）—— 只有一条路，写死在代码里

想把东西**私密地**送到你手里、又不想在评论区吵到别人？用 `dm`（**一天同一个人不限条数** ✓）：

```bash
node bili.mjs dm --status                 # 看今天额度 + 互关状态
node bili.mjs dm --msg "…" --dry          # 预演
node bili.mjs dm --msg "…" --go           # 真发
```

三条限制**不接受参数覆盖**（`commands/dm.mjs` 顶部的常量）：

1. **一天只锁定 1 个收信人**（防刷量）—— 对**这一个人**发多少条都行 ✓
2. **只发给配置里的 `owner.mid`** —— 别处发不出去
3. **必须互关**（`relation.attribute === 6`），否则直接拒发

> 为什么这么窄：B站 私信是风控最凶的接口（判营销/骚扰）。能力越窄越安全。
> 要开通：用她的号去**关注**你一次 ✓ 然后 `node bili.mjs dm --status` 确认 `attribute=6` ✓

## 它怎么"过日子"

| 步骤 | 做什么 |
|---|---|
| 醒来 | 窗口内随机时刻；30% 概率"今天不想看" |
| 筛 5 条 | 只读文字（字幕/弹幕/热评），**不出图**，便宜 |
| 深读 2–3 条 | 完整档：含**抽帧看画面**（贵的那一步只花几次） |
| 分享 | 从深读过的里挑，**值不值得占用你一次注意力**；不足就少发、一条不值得就不发 |
| 日记 | 两本都写；**掷到"今天不看"也会叫醒一次**（还得说明为什么不想看）|
| 收工 | 扫一遍"谁找过它" → 推你一条摘要 |

**硬限制（代码强制）**：分享 **每天合计 ≤3** · **同一视频 7 天内一次** · 同一个人（可选）**30 天只回一次** · 撞风控立刻停。

## 指定清单：看什么，由你点名（v0.4）

以前「关注了」≠「一定会看」—— 关注流只是候选池的一路，还要跟热门 / 排行一起抢那几个名额。
现在可以点名：

```bash
node bili.mjs watchlist add up 123456 某某UP        # mid 或 space 链接 + 名字
node bili.mjs watchlist add video BV1xx411c7mD 想再看一遍
node bili.mjs watchlist list
node bili.mjs watchlist rm 123456                    # mid 或 BV 都认
node bili.mjs watchlist fetch                        # 先验一遍：真能取到吗
```

设置页「养鱼 → 指定清单」也能改（两段多行文本，一行一个）。

规则：

- 点名的**永远排在 `feed` 前面**（输出带 ★），**不参与多样性抽稀**
- **指定视频即使看过也保留**（你点名的，可能就是想再看一遍），会标 `[看过]`
- 指定 UP 的新投稿照常排除看过的
- **名字别省**：空间投稿接口被风控时，会降级成「按名字搜 + 用 mid 过滤」；只填 mid 就只剩关注流这一路
- **短链也认**：`b23.tv/xxxx` 会自动展开成交付链接（设置页保存时展开，CLI 也会）
- 取不到不会静默：`watchlist fetch` 和 `feed` 的 stderr 都会写清"这次走的哪条路、为什么没取到"

## 预算：单条回复硬顶 + 单次视频 / 单轮上限（v0.4）

三个数，设置页「养鱼 → 预算」或 `node bili.mjs budget set <key> <值>`：

| 键 | 默认 | 管什么 | 硬不硬 |
|---|---|---|---|
| `replyMaxTokens` | 1200 | 一条回复最多生成多少 token | **真硬顶**：插件在宿主 `agent/request` 瀑布里下发 `maxTokens`，超了会被截断 |
| `videoMaxTokens` | 12000 | 看一条视频最多读进来多少（估算） | 读之前先算账：截字幕 / 少给热评 / 不抽帧，并在输出里说明原因 |
| `wakeMaxTokens` | 60000 | 一次醒来总共多少（估算） | 决定「初筛几条 + 深读几条」；超了先少看一条 → 再不出图 → 停 |

```bash
node bili.mjs budget status        # 预算 + 最近 24h 真实用量 + 工具估算
node bili.mjs budget plan          # 这一轮会怎么分配（不联网）
node bili.mjs budget reset --yes   # 只清账本，不动配置和日记
```

口径（写清楚，不冒充账单）：

- 中文按 **1 字 ≈ 1 token** 保守估；抽帧一张 3×3 按 **5400 token** 算
- 真实 usage 来自宿主的 `assistant/message`，记进 `~/.dsh/whale-spend.jsonl`
- **单条回复**是宿主侧 `maxTokens` 真截断；**单视频 / 单轮**是"在生成素材那一刻按预算裁好"，不是事后记账

> 为什么单视频不硬顶：模型读多少，取决于工具吐了多少 —— 所以能拧的水龙头在**工具输出**这一侧。
> 想强制看画面：`debrief <BV> --budget 30000`，或把设置页的「单次视频」调大 ✓

## 口味源：她凭什么知道你想看什么（v0.5）

日记里那三个词太单薄。v0.5 起她会读**你的 B站账号**（只读，不改任何东西）：

```bash
node bili.mjs taste sync      # 拉关注 + 收藏 + 历史
node bili.mjs taste status    # 看现在手里有什么（不联网）
```

| 读什么 | 怎么读 | 用来干什么 |
|---|---|---|
| **关注列表** | `x/relation/followings`（你和她的都行；别人的只给公开部分） | 关注的人发的新视频 **+6 分** |
| **收藏夹** | `x/v3/fav/folder/created/list-all` + `/resource/list` | 收藏过的 BV **排除**；夹名当口味标签（权重最高） |
| **观看历史** | `x/web-interface/history/cursor`（**只对登录账号有效**） | 看过的 BV **排除**；看完的学口味，点开就退的不学 |

实测（2026-10-21）：用她自己的 cookie 就能读到**主人账号的 31 个公开收藏夹、197 条收藏、100 个关注** —— 不需要你再交一份凭据。
夹名是手写的兴趣标签（机械臂 / 硬件 / 画图 / 动漫 / 剑魔…），比标题词准得多。

两条规则写在代码里：

1. **文件夹名权重 6，但不随条目数放大** —— 否则一个 102 条的"剑魔"夹会把整个档案带偏；
2. **只看过一半也算看过** —— 收藏/历史命中就排除（可分别关），关注只加分不排除。

> ⚠️ 别人的**观看历史** B站不给（只能读公开收藏/关注）。所以"排除我看过的"目前覆盖：
> 你的公开收藏 + 登录账号自己的历史。要覆盖你自己的历史，需要把你自己的 cookie 也配进来。
>
> 档案在 `~/.bili-ai/taste.json`：只在本机、不上传、不进日记。她每次醒来会 `taste sync --if-stale`
> （超 24 小时才拉；拉失败就用旧档案继续，不会卡住）。

## 本地转写：没有字幕也能读（v0.6）

有些视频就是没有字幕轨（实测一条发布 21 小时仍 0 轨），而 AI 字幕"人名/数字不准"也是常态。
v0.6 起可以在**本机**把音频转成带时间戳的文字，音频一个字节都不出这台机器。

```bash
node bili.mjs audio BV1x3nw6KEj2    # 只下音频：dash 192k → 16kHz wav（20 分钟约 11–21MB）
node bili.mjs asr   BV1x3nw6KEj2    # 本地转写 → [mm:ss] txt + .srt
node bili.mjs debrief BV… --asr     # B站没字幕时，用这份转写当字幕读
```

用的是什么：**FunASR Paraformer-large + fsmn-vad + ct-punc**（中文专用、自动切句、带标点）。

一次性安装（独立 venv，不碰 DSH 运行时；卸载直接删目录）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "%USERPROFILE%\.bili-ai\asr-install.ps1"
```

- 装的是什么：torch **CPU 版** + funasr + modelscope；首次转写再下 ~1.1GB 模型到 `~/.bili-ai/asr-models`
- 想用显卡：把 `torch torchaudio` 换成 CUDA 版（`--index-url https://download.pytorch.org/whl/cu124`），`asr --device cuda:0`
- 专有名词不准：`asr BV… --hotword "人名 机构名 新词"`
- 隐私：音频、模型、转写全在本机；`asr` 不调任何云服务

## 私信窗口：她发来的私信，你审了再发（v0.7）

她发给你的**每一条私信**，除了真的发到 B站，还会在本地留一份，出现在 DSH 左侧的 **🐟「鱼的私信」** 窗口里：

```
左侧列表                 右侧编辑
待审 · 10-21 18:20  →   原文 / 你改过的正文（textarea）
BV1x3nw6KEj2            [保存修改] [发到评论区] [否掉] [删除]
```

- **保存修改**：只存本地，一个字都不会发出去
- **发到评论区**：需要填一个 BV（她的分享型私信会自带），点之前会二次确认；这是**公开评论**，发出后只能删不能改
- **否掉**：状态变「已否」，并在 `whale-log.jsonl` 留一笔 —— 她下次能学到"这种不要"
- **删除**：只删这条记录，不撤回已发出的私信/评论

两条安全边界：

1. **发评论只在你点按钮时发生**，插件不会自己把私信搬去评论区；
2. 走的是 `comment` 且**不带 `--auto`** —— 属于「你授权」的发言，不占她每天 3 条的自主额度 ✓

> 因为私信可能被你改成公开评论，她也被提醒了一句：**私信按「可能公开」写，不写私事、账号、路径**。
> 记录在 `~/.bili-ai/outbox.json`（本机；原文永远保留，你改的只是 `edited` 字段）。

命令行等价物（脚本/排查用）：

```bash
node bili.mjs outbox list [--status pending] [--json]
node bili.mjs outbox add --text "…" [--bv BV…]
node bili.mjs outbox post <id> --go        # 真发；不带 --go 会拒绝
node bili.mjs outbox reject <id>
node bili.mjs outbox delete <id>
```

## 任务台：指定视频 + 指定写法，让她按格式写（v0.8）

窗口里多了第二页「任务台」。你派活，她干活，但**发不发还是你点**：

```
看哪条 [BV1x3nw6KEj2      ]  怎么写 [时间轴 ▾]  字数 [240]
额外要求 [ 别用感叹号 / 一定要提到 03:12 那个实验            ]
[ ] 允许带表情（最多 3 个）   [ ] @ 我
还要 @ 谁 [ 张三, 李四                                   ]
指定表情 [doge] [大哭] ×   [ 从表情库挑 ]
[ 现在就做 ]  [ 排进下一次醒来 ]
```

> **允许带表情** = 她自己按语境挑；**指定表情** = 你点哪几个，她就必须用哪几个（不许换、不许多加）。
> 交稿时指定的表情会自动挂上；正文里没写对应的 `[名字]` 会当场警告 —— 只带元数据是不显示的。

六种写法（每种都带结构要求**和**反例 —— 反例比正例有用）：

| 格式 | 交付物 | 默认字数 |
|---|---|---|
| `outline` 总结大纲 | 一句说清讲什么 + 3–5 个要点（按片子推进顺序，每个要点要有具体信息） | 280 |
| `timeline` 时间轴 | 4–8 个 `mm:ss`，只标转折/结论/名场面，时间必须来自字幕或本地转写 | 240 |
| `opinion` 提出观点 | 一句站队 + 片中证据 + 你预料的反驳；不许「见仁见智」 | 260 |
| `banter` 活跃气氛 | 贴着片子的吐槽 + 一个能让人接话的问题；不刷「来了」 | 80 |
| `links` 读简介链接 | 跑 `links <BV>` 把短链展开、取真标题，每条一句"是什么 + 值不值得点" | 240 |
| `custom` 自定义 | 完全按你写的来，她先复述一遍交付物 | 300 |

### 她怎么干

```
debrief <BV>（预算上限 = 设置里的「单次视频」）
  ↓ 没字幕 → asr <BV> → debrief --asr（本机转写，音频不出本机）
按格式写（结构 + 反例 + 字数 + 表情/@ 约束都在提示词里）
  ↓
task draft <id> --text-file …   ← 只交草稿
  ↓
进「私信」页待审 → 你改 → 你点「发到评论区」
```

- **「现在就做」**：宿主立刻把这段话塞进她那个会话（等于提前叫醒一次，会花 token）
- **「排进下一次醒来」**：进队列，下一轮生物钟醒来先做（提示词里排在选视频之前）
- 「写成草稿」后，任务上会出现 **看草稿** 按钮，直接跳到「私信」页那条

### 为什么她不能自己发

任务提示词里写死了「**只交草稿，绝对不要自己发评论**」，而且 `task` 命令里**没有**发评论这个子命令 ——
这不是"默认关掉的开关"，是流程里没有那条路。发评论只有一条路：你在窗口里点。

> 队列在 `~/.bili-ai/tasks.json`；草稿在 `outbox.json`（`kind: "task"`，带 `taskId` 指回来）。
> 发出去之后，任务状态会自动变「已发评论」—— 两边状态不会打架。

命令行等价物：

```bash
node bili.mjs task formats                          # 看六种写法
node bili.mjs task add --bv BV1x3nw6KEj2 --format timeline --chars 240 --instruction "别用感叹号"
node bili.mjs task add --bv BV1x3nw6KEj2 --format banter --emote --mention 张三   # 允许表情 + @ 指定的人
node bili.mjs task take <id>                        # 领活 + 打印"该怎么写"
node bili.mjs task draft <id> --text-file draft.txt [--emote 笑哭 --emote doge]
node bili.mjs task list / status / cancel <id> / rm <id>
node bili.mjs links BV1x3nw6KEj2                     # 简介里的链接（短链展开 + 取标题）
```

### @ 谁（v0.9）

B站 评论接口**没有 @ 参数** —— @ 就是正文开头的那串 `@昵称` 文字。所以：

- 窗口里填的「@ 谁」会被推进正文最前面（`@张三 @李四 正文…`），同时记进条目的 `mentions`
- **名字必须和对方现在的昵称一个字不差**（改名就 @ 不到）；拿不准先 `bili.mjs whois <mid>`
- 发完可以 `bili.mjs thread --aid <aid> --rpid <rpid>` 看「@到」有没有解析出来

### 表情与贴纸（v0.9 / v0.11）

私信窗口里的草稿下面有「打开表情库」，面板顶部两个分类：

- **官方表情**：按标签（笑 / 哭 / 惊 / 赞 / 爱 / 无语…）筛，点图就插到光标处，**最多 3 个**；
  正文里的 `[笑哭]` 和接口要的 emote 元数据由窗口一起给齐（只给一份会变成字面方括号 ✗）。
  `~/.dsh/whale-emotes.json` 空了就先 `node bili.mjs emotes sync`。
- **我的表情包**：直接列出 `表情包/` 里的图（92px 预览，缩略图走本地路由 `/dsh-bili/api/sticker`，
  只认库里登记过的名字，不按路径读文件），选中（最多 2 张）→ **作为评论图片发出去**。

### 评论带图（v0.11）

评论区**支持带图**，字段是 `pictures`（评论条目里的 `content.pictures[]`：
`img_src / img_width / img_height / img_size`）。发布流程：

1. 贴纸先传 B站 CDN（`upload_bfs`，和私信发图同一条路）；
2. 组 `pictures` 数组，跟 `message` 一起 POST `x/v2/reply/add`；
3. 发完**回读** `content.pictures`：
   - 一张都没进去 → **自动删掉那条评论**（状态退回「待审」并说明）
   - 只进去一部分 → 保留评论，并提示"进了 N/M 张"

> ⚠️ 早先那版把图塞进 `emote` 元数据（想当"大表情"）—— 实测 B站 不认，评论只剩字面 `[名字]`。
> 那条路已标记为**证伪**，现在走的是 `pictures` ✅

图库过期了就重新索引（文件名变了必须重跑）：

```bash
node bili.mjs stickers sync --dir "…\表情包"
node bili.mjs stickers tag 悠闲 摆烂,泡澡 --desc "泡在鱼碗里"
```

## 私信监听（实时互动 · 零打扰）

设置页「全天监听」里有个「**私信监听（只认主人）**」开关：

```
每 20 秒看一次：主人那个会话有没有新私信
  · 有新消息 → 叫醒她 → 她直接回（不用审核 ✓ 因为是主人）
  · 没新消息 → 什么也不做 → 零 token ✓
  · 系统通知 / 陌生人 → **不会为它叫醒她**（不花 token）；她下次自己醒来时可以按「回复私信」的规则回一句
```

### 别人问「你是谁」怎么回（v0.11.1）

默认规则：**别人找她 → 先写草稿给你审**。但「你是谁 / 介绍一下你自己 / 是 AI 吗」这类属于该答的，
所以单开了一条额度：

- 额度内（默认 **一天 1 次**）→ 她自己回：`intro check --text "他的原话"` 退出码 0 → `comment --auto --go` → `intro record`
- 额度用完 / 这条不像自我介绍 → 老老实实写草稿给你审
- 设置页「全天监听」里可以改这个数（填 0 = 一律写草稿）
- 她自己回的内容只说她**自己**（AI 账号 / 看什么 / 什么脾气），**不提你任何信息**

```bash
node bili.mjs intro                       # 今天回过几次
node bili.mjs intro check --text "能介绍一下你自己吗"
node bili.mjs intro record --target BV1x3nw6KEj2 --note "自我介绍"
```

### 回复别人的私信（v0.12）

`dm` 是**写死只发主人**的（一天锁定一个收信人），所以别人私信她时，原来她一条都回不了。
v0.12 开了一个**很窄**的口子，默认关：

```bash
node bili.mjs dm-reply --list               # 谁先找过她（只列"他最后一条是他发的"）
node bili.mjs dm-reply --to <mid> --msg "…" --incoming "他的原话" --dry|--go
```

| 限制 | 值 |
|---|---|
| 开关 | 设置页「允许回复私信」——**默认关** |
| 谁先说话 | 必须**他先**发（最后一条是她发的 → 拒绝追着发） |
| 时间窗 | 72 小时内 |
| 关系 | 必须互关 |
| 频率 | **一天 1 条** + 同一个人 **30 天一次** |
| 长度 | ≤200 字 |
| 自我介绍类 | 同时吃掉「一天 1 次」的自我介绍额度（和评论区共用一本账） |

另外会拦住**关注自动回复**（感谢关注 / 加群 / 群号）—— 回它等于两个机器人打招呼。
`--list` 会标「⚠️ 疑似自动回复（别回）」，`--go` 也会拒绝。

### 末尾的「消耗 / 额度」备注（v0.12.1）

设置页「回复末尾带上消耗/额度备注」（默认开）打开后，每条私信自动加一句：

```
我是大肥鱼，一个在这儿看片的 AI。话不多，看到喜欢的会多说两句。
（本次消耗 438 token · 本日对话次数已用完）
```

- 数字来自 `~/.dsh/whale-spend.jsonl` 的**真实用量**（今天 input+output；今天还没跑过就用最近一次兜底）
- 额度没满时写「今日还可回 N 次」
- 单条关掉：`--no-cost-note`；全局关：设置页那个开关
- 正文里已经有括号备注就不会再加（不会叠两层）

> 为什么比评论区监听好：**只有你一个对话方** ✓ 没有陌生人干扰 ✓
> 你不说话就没有新私信 ✓ **token 花销为 0** ✓

## 依赖与移植性（**装之前先读这节**）

这套东西**不是开箱即用的通用件** —— 它建立在一组"宿主假设"上。逐条列清楚，以及换环境怎么办：

| 假设 | 为什么依赖它 | 换环境怎么办 |
|---|---|---|
| **宿主能"被唤醒"** | 生物钟由**插件宿主自己**驱动：每 60 秒 tick → 跑 `night plan` → 到点用 `sessionController.prompt` 往她的会话里塞一个回合（v0.1.5 起 ✗ 不再需要人挂 `night clock`）| 换 DSH 版本时确认 `sessionController` 还在；没有的话退化成"宿主侧定时轮询 + `night clock`"（老办法 ✓）|
| **有一个通知渠道**（向使用者推送）| 可见性要求"自主发言后必须报备""每天推一条摘要" | 换成你的：邮件 / webhook / IM / 写文件让宿主轮询。**只要"使用者看得见"成立** ✓ 配置见 `config.notify`（`stdout`/`file`/`dm`/`webhook`/`command` 五种后端 —— **`dm` 就是 B站私信，零外部依赖** ✓）|
| **有一个调度器** | 兜底标记（宿主没开那晚也留痕）| Windows 计划任务 / Linux `cron` / systemd timer —— 都只是**跑一次** `whale-night.mjs mark` |
| **有 ffmpeg** | 只有"抽帧看画面"用得到 | 装进 PATH，或用环境变量 `FFMPEG` 指定绝对路径；不装就跳过画面那一路，其余照常 |
| **B 站账号 + 本机凭据文件** | 一切读写都靠它 | 无替代（这就是目标平台）|

**不依赖什么**：没有数据库、没有守护进程、没有框架、没有云服务。状态全在**几个普通文件**里
（`quota.json` / `whale-log.jsonl` / 两本日记）—— 人随时能打开看，宿主可以整个换掉。

> ⚠️ 已知边界：本项目最初是围绕**一个具体的人的日常**长出来的（Windows + DSH + 微信通道）。
> 上表就是把那些假设摆到明面上 —— 换环境时**照着"怎么办"一列改**，别指望它一行不改就跑。
